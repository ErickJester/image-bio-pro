# Glosario

Términos nuevos del proyecto, definidos con mis palabras. En orden alfabético.

| Término | Qué es | Dónde lo vi |
|---|---|---|
| `.gitignore` | Lista de archivos y carpetas que Git no debe subir al repositorio | Módulo 1 |
| Desarrollo guiado por riesgo | Empezar por la parte con más probabilidad de salir mal, no por la más fácil | Ingeniería de software |
| Desarrollo incremental | Agregar una mejora a la vez sobre algo que ya funciona | Ingeniería de software |
| Entorno virtual (`venv`) | Carpeta del proyecto con su propio Python y sus propias librerías, aislada del resto de la computadora | Módulo 1 |
| Esqueleto que camina (*walking skeleton*) | Versión mínima del flujo completo, de punta a punta y ya publicada | Ingeniería de software |
| Fuera de alcance | Lo que explícitamente no se va a hacer en esta entrega | Ingeniería de software |
| Historia de usuario | Requisito escrito como "como [usuario] quiero [acción] para [objetivo]" | Ingeniería de software |
| `pip` | Programa que instala librerías de Python dentro del entorno activo | Módulo 1 |
| Política de ejecución | Configuración de seguridad de PowerShell que decide qué scripts `.ps1` se pueden ejecutar | Módulo 1 |
| Prototipo de baja fidelidad | Boceto sencillo para validar con el cliente qué se va a construir | Ingeniería de software |
| `py` | Lanzador de Python en Windows que permite elegir la versión, por ejemplo `py -3.12` | Módulo 1 |
| `requirements.txt` | Lista de librerías del proyecto para instalarlas igual en cualquier computadora | Módulo 1 |
| Requisito funcional | Algo que el sistema hace, por ejemplo contar las células; debe salir de lo que pidió el cliente | Ingeniería de software |
| Requisito no funcional | Cómo lo hace el sistema o qué condiciones cumple: rapidez, seguridad, facilidad de uso | Ingeniería de software |
| Restricción | Condición fija que limita el proyecto, como la fecha de entrega o los datos disponibles | Ingeniería de software |
| Spike | Experimento corto para averiguar si algo se puede hacer antes de comprometerse | Ingeniería de software |
| Suposición | Algo que el programador decide o da por hecho sin que el cliente lo haya dicho; no es un requisito | Ingeniería de software |
| Terminal | Ventana para dar órdenes escritas a la computadora; en Windows es PowerShell | Módulo 1 |
| Validación de requisitos | Confirmar con el cliente que lo entendido es lo que quiere | Ingeniería de software |
